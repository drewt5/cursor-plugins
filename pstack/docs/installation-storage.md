# Internal retained package storage

`stagePackage({ source, root })` in `scripts/lib/installation-storage.mjs` copies only the portable payload into an unpredictable `.pstack/releases/.stage-*` directory on the installation filesystem. It preserves file modes, checks the canonical byte/executable-mode digest and source stability, writes detached provenance, and renames the complete payload to `.pstack/releases/<digest>`. It verifies all stored files and rejects symlinks, unexpected files, digest changes and provenance mismatches. An existing digest directory is inspected; its name alone is never proof. Reusing identical verified content retains that stored copy's provenance rather than inventing a new origin for unchanged bytes.

Staging does not publish a receipt, replace `.pstack/package`, activate host files, migrate legacy directories, or delete old releases. Failed staging removes only its own unpredictable scratch directory; it may leave empty storage parents. Callers will serialize mutation with the scoped installation lock. This internal API is not a public update command.

`verifyGeneration(root, generation)` validates a retained descriptor against the fixed local storage path. `renderStagedArtifacts({ root, generation, targets, opencodeRoot, global, config, hostObservations })` calls that verified payload's retained `scripts/lib/installation-artifacts.mjs:renderArtifacts` contract 1. It accepts the current effective model configuration and proposes artifacts without writing configuration or invoking providers. Only the supported current/previous generation and the explicit legacy migration baseline are recovery inputs; arbitrary historical renderer compatibility is not promised. Recovery execution is supplied by #18, not this renderer contract.

Proposed artifacts refer to the stable `.pstack/package` path, a relative link to the selected local generation. Host skill links, OpenCode command instructions and agent references use this location, so project relocation and source-checkout removal preserve references. Write operations use the real `.pstack/releases/<digest>` path and replace the stable link itself. They never write a child through `.pstack/package`; existing `safePath` symlink-parent rejection remains intact. Public installation continues using its existing copied package until the single cutover in #20, after journal activation, recovery and rollback pass.
