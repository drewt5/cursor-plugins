# Lifecycle and manifesto acceptance

A candidate is reviewed using exact source, required-run/attempt, tested checkout and package identities. Completion of the roadmap is not a blanket certification of future commits. The self-contained candidate record attached to the implementation PR binds the current eight required jobs, six reports, upstream review, public-clone cases, manifesto audit and cost comparison. `release-candidate.mjs --lifecycle-evidence FILE` validates that binding and marks a complete record `verified-for-maintainer-review`; without fresh evidence the lifecycle gate stays pending. Neither status publishes a tag/release or proves model reasoning.

## Explicit public-clone integration

Requires Git, Node 20+ and the Codex version in [tested-hosts.json](../tested-hosts.json). Supply already-installed prerequisites; this check never installs/downgrades providers. It makes a fresh public HTTPS clone with disposable home/config/cache/state and disabled user/system Git configuration, selects an exact commit, and uses only that checkout for installation. No private sibling repository, existing pstack or maintainer credentials are used. Network access belongs to this explicit integration check, not offline PR jobs.

```sh
pstack_candidate=REPLACE_WITH_EXACT_CANDIDATE_COMMIT
node pstack/scripts/check-public-lifecycle.mjs --candidate "$pstack_candidate" --output /tmp/pstack-public-lifecycle.json
```

The resulting record and command logs are outside the package. It asserts coherent global qualified Codex pstack plus a project third-party bare same-name skill; later ownership/local-edit refusals; the printed retained recovery command while the checkout is absent; rollback preserving current config; relocated full uninstall; and the actual immediately previous portable tag or initial legacy Git baseline through its original installer. It compares user bytes/modes, links, receipts, package identities and native origins. Simulated user conflicts are preserved before explicit user resolution; the installer does not silently remove them. Existing offline tests cover unknown provider-version transitions and model adapters. Native lanes cover all three pinned providers and both Claude methods. Cursor remains static evidence.

[Installation](install.md) gives the ordinary single apply command from an already-selected checkout, optional preview, recovery, rollback and uninstall. [Release selection](releases.md#select-and-install-a-published-portable-release) supplies clone/fetch/tag/detached-checkout preparation separately. For a pre-tag candidate, select its exact commit and run the local version check; do not invent a published tag. No mandatory doctor, manifest editing, policy selection or automatic latest downloader is introduced.

## Cost and drift review

The baseline is successful push run [38080504980](https://github.com/drewt5/cursor-plugins/actions/runs/38080504980) at `b6a7cf63be907de2b088007ee6e00b9909e71bf6`, attempt 1. Its portable execution phases were 7.565s Linux and 13.418s macOS. The public-cutover sample [38096013691](https://github.com/drewt5/cursor-plugins/actions/runs/38096013691), attempt 1, measured 47.479s Linux and 137.446s macOS; native OpenCode discovery was 43.013s, versus 5.246s before lifecycle/scope/recovery coverage. Its source was `51743e52353b6fbfde430b9a7b46a0fc579eb10e`, tested merge checkout recorded in its reports.

The final record adds the final current-head sample, all eight job start/end/step intervals, each phase duration, and critical-path wall time. Pre-job wait includes runner queue and matrix dependency wait; setup/finalization/upload are separated from reported test execution. Samples differ in event and runner context and are operational evidence, not a controlled benchmark. The substantive added cost is exercised recovery/ownership/native scope behavior. Identical generation descriptors are verified once within each synchronous journal parse; later calls always revalidate current bytes, with no cross-operation cache. The compact fixture optimization removes unrelated library copying/hashing from repeated boundary tests without removing crash boundaries or native/full-package scenarios; it introduces no new job matrix, background benchmark or timeout relaxation.

[Canary triage and promotion](ci.md#triage-provider-drift) remains advisory and separately classifies upstream drift, provider drift, user-install conflicts, infrastructure noise and unsupported native visibility. Required pinned checks alone supply baseline release proof. Use doctor for user installation facts and the source-bound release-candidate record for maintainer readiness. The final evidence records the actually observed latest-canary result, including intentional failure fixtures or pending runs; a past green advisory run is never promoted silently to a supported provider pin.

## Cost evidence fields

New validation requires `cost.baseline`, `cost.current`, and nonempty `cost.assessment` text. Archived records remain historical evidence. Records without the fields below fail new validation; collect the missing measurements rather than changing archived bytes or inventing zeros.

Each sample records `runId` as a positive safe integer or its decimal string, positive integer `runAttempt`, exact 40-character lowercase hexadecimal `sourceHeadSha`, `event`, `url`, `conclusion: "success"`, and parseable `createdAt`. Allowed events are `push`, `pull_request`, `workflow_dispatch`, and `merge_group`. The URL identifies that run in `drewt5/cursor-plugins`. Each sample also contains `criticalPathSeconds`, `eventToLastJobSeconds`, `reportDigests` keyed by the six required report checks, `checkoutLogDigest`, and `jobs`. Digests are 64-character lowercase hexadecimal SHA-256 values.

`jobs` contains each required job exactly once. The authoritative job names, report checks, and phases live in `scripts/lib/release-evidence.mjs`. Each job records `name`, a unique positive safe-integer `id`, `conclusion: "success"`, `start`, `end`, `durationSeconds`, `preJobWaitSeconds`, `steps`, `executionPhases`, and `phaseExecutionSeconds`. Baseline job IDs belong to a different run and cannot reuse current IDs. Array order has no meaning.

Each step records a unique nonempty `name`, `durationSeconds`, and `status`. This `status` is the GitHub conclusion, either `success` or `skipped`, not the lifecycle status `completed`. Zero elapsed time is valid, including for skipped steps. Missing duration is invalid. Each execution phase records `phase` and `durationMs`. The matrix preparation and required gate jobs have empty phase arrays; all other jobs require their exact report phases.

All durations must be finite nonnegative numbers. The validator checks `createdAt <= start <= end`, job elapsed time, and pre-job wait against timestamps. It recomputes the critical path as latest job end minus earliest job start, and event-to-last-job time as latest job end minus run creation. It checks `phaseExecutionSeconds` against the sum of phase milliseconds divided by 1000. Arithmetic permits at most 0.001 second of conversion error. It does not sum job durations for wall time or require phase time to equal or fit a GitHub step interval. GitHub timestamps use second resolution and account for different overhead.

The current sample must match the validated required run, attempt, source, event, job name/ID pairs, step names/conclusions, report digests, checkout-log digest, and each phase duration. The baseline also requires `reportProvenance` with `sourceHeadSha`, `testedSha`, `runId`, `runAttempt`, and `checkoutLogDigest`. The run and checkout fields must match the baseline sample. For a non-PR baseline, the tested commit equals the source commit. For old reports only, `reportProvenance.sourceHeadSha` may be null if `limitation` is exactly `cost-only historical reports lack sourceHeadSha`. The sample's known source commit and actual tested commit are still mandatory. `reportProvenance` is baseline-only and cannot relax current evidence validation.

## Collect cost measurements

Use the selected Actions run metadata for the run identity, conclusion, and creation timestamp. Use that attempt's jobs API for job IDs, conclusions, start/end timestamps, and step names, conclusions, and `started_at`/`completed_at` timestamps. Derive each step's `durationSeconds` from those timestamps; missing timestamps require recollection, not a default zero. Preserve explicit successful run and job conclusions. Download all required reports and checkout logs from the same attempt using the [CI protocol](ci.md). Compute digests from their retained bytes and copy execution phase names and milliseconds from the reports. Derive elapsed totals from timestamps rather than estimates. Retain the baseline's report source and tested commit plus its run and checkout provenance. The tiny fixture in `tests/fixtures/lifecycle-evidence.mjs` illustrates the accepted structure; its synthetic values are not release evidence.

Validation checks structure, arithmetic, and correspondence with the supplied required evidence. It does not authenticate handwritten baseline measurements, prove scenario execution from a log digest, or judge the P1-P10 audit prose. The required result does not retain raw GitHub timestamps or step durations, so their validation checks arithmetic and numeric shape rather than equality with raw API data. Those measurements remain unsigned maintainer attestations.
